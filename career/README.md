# career/

Internships, jobs, research positions, and the search itself.

| Page | Type | Template | What it holds |
|---|---|---|---|
| `application-profile.md` | `profile` | `application-profile.md` | Reusable form answers, resume routing, long-answer pointers. Nothing secret. |
| `application-log-<cycle>.md` | `application-log` | `application-log.md` | One page per search cycle (e.g. summer internships): what you applied to, with which resume, status, next step, source. A plan silo: close it with `status: resolved` when the cycle ends. |
| `resume.md` | `note` | `resume-pointer.md` | Pointer to the current resume PDFs in `raw/career/` and what changed between versions. Never paste the resume text. |
| `research-lab-prospects.md` | `note` | `lab-prospects.md` | Labs and faculty you might join, with status. |
| other plans | `plan` | `plan.md` | e.g. a grad-school exploration. |

Entity pages for employers or labs, if you make them, link to the log; they never absorb it. Offer terms, deadlines and recruiter claims carry `[Source: ...]`. Interview notes from a recording follow the transcript rule in AGENTS.md §Write.

DEMO pages (fictional student Alex Example): `application-profile.md`, `application-log-2100-summer.md`, `resume.md`, `research-lab-prospects.md`. Delete them once you add real pages.

Allowed types: `profile`, `application-log`, `plan`, `note`. Commit scope: `career`.
